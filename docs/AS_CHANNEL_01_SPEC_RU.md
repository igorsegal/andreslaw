# AS_Channel_01 — спецификация
Дата: 2026-10-06
Статус: PROJECT_FORMALIZATION / RESEARCH
## Цель
Создать собственный простой и полностью прозрачный канальный индикатор,
который функционально заменяет SWTch для поиска экстремальных областей.
Индикатор НЕ должен копировать внутреннюю формулу SWTch.
Основные требования:
- простая математика;
- полностью открытый код;
- отсутствие скрытых состояний;
- работа только на рыночных данных;
- пригодность для автоматического тестирования;
- одинаковая геометрия независимо от размера депозита;
- отсутствие торговой логики внутри индикатора.
## Архитектура
Пять основных линий:
CENTER
INNER_HIGH
INNER_LOW
OUTER_HIGH
OUTER_LOW
## Базовая математическая модель
CENTER:
сглаженная цена.
На первом этапе рассматривается EMA.
VOLATILITY:
стандартное отклонение цены относительно CENTER
за заданное окно.
INNER_HIGH:
CENTER + K1 * VOLATILITY
INNER_LOW:
CENTER - K1 * VOLATILITY
OUTER_HIGH:
CENTER + K2 * VOLATILITY
OUTER_LOW:
CENTER - K2 * VOLATILITY
где:
K2 > K1
## Назначение линий
CENTER:
центральное состояние цены.
INNER_HIGH / INNER_LOW:
рабочая экстремальная зона.
Используется для определения первого входа цены
изнутри канала наружу.
OUTER_HIGH / OUTER_LOW:
внешняя volatility boundary.
Это НЕ торговый стоп и НЕ автоматическая команда выхода.
Она является только рыночным ориентиром возможной инвалидизации
или экстремального расширения волатильности.
## Экспортируемые buffers
buffer 0 = CENTER
buffer 1 = INNER_HIGH
buffer 2 = INNER_LOW
buffer 3 = OUTER_HIGH
buffer 4 = OUTER_LOW
Никаких дополнительных скрытых buffers в версии 01.
## События
LOWER_ENTRY:
previous Low > previous INNER_LOW
AND
current Low <= current INNER_LOW
UPPER_ENTRY:
previous High < previous INNER_HIGH
AND
current High >= current INNER_HIGH
Simple occupancy:
Low <= INNER_LOW
или
High >= INNER_HIGH
НЕ считать отдельным событием,
поскольку один выход может создавать много последовательных баров.
## Outer boundaries
Внешние границы являются опциональными.
Их наличие не должно влиять на расчет INNER channel.
Они могут быть отключены визуально,
но их расчет должен оставаться детерминированным.
## Risk principle
Размер депозита НЕ изменяет геометрию канала.
Размер позиции определяется отдельно:
allowed monetary risk
/
stop distance value
Если минимальный торговый объем брокера
не позволяет выдержать допустимый денежный риск,
сделка должна быть запрещена.
Нельзя искусственно сужать рыночную границу
только из-за маленького депозита.
## Calibration policy
Параметры:
EMA period
volatility window
K1
K2
НЕ выбирать как окончательные "на глаз".
Первая версия должна использовать исследовательские параметры,
после чего они сравниваются с уже найденными SWTch W4 CHANNEL_ENTRY events.
Основные метрики сравнения:
1. сколько SWTch CHANNEL_ENTRY воспроизведено;
2. временная ошибка между событиями;
3. число дополнительных ложных entry;
4. стабильность на других временных участках;
5. стабильность на других инструментах.
SWTch используется только как временный benchmark,
а не как обязательная математическая модель.
## Ограничения версии 01
Нет:
- торговых сигналов;
- открытия позиций;
- закрытия позиций;
- расчета lot;
- ATR stop logic;
- Pattern logic;
- SWTtr logic;
- SWTsr logic.
AS_Channel_01 является только market geometry provider.
## Acceptance principle
Предпочтение отдается более простой модели,
если она воспроизводит практически полезные экстремальные события
с сопоставимой эффективностью.
Production integration запрещена
до отдельного runtime comparison test.
