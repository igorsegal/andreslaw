# AS — спецификация Pattern 1..3
Дата: 2026-10-05

## 1. Назначение
Документ разделяет:
1. базовый Pattern, используемый как разрешение открытия сделки;
2. расширенные графические паттерны SWT — разворот, восстановление и другие состояния.
Эти два слоя нельзя смешивать в одной недоказанной логике.

## 3. Состав Pattern
Pattern образуют три младших тренда:
- Level 3 — Daily;
- Level 2 — IDay;
- Level 1 — Hourly.
Уровни Weekly..Basic относятся к Trend и в Pattern не входят.
Intrahour/W2 является отдельным непосредственным торговым сигналом и также не входит в Pattern.
## 4. Базовый Pattern открытия — актуальная версия
Для открытия новой позиции:
- если Hourly, IDay и Daily направлены вверх -> Pattern=UP;
- если Hourly, IDay и Daily направлены вниз -> Pattern=DN;
- при любом конфликте направлений -> Pattern=NO;
- при отсутствии валидных данных обязательного компонента -> Pattern=NO.
Это fail-closed правило Andreslaw.
## 5. ContrTrend
ContrTrend изменяет результирующее направление Trend.
Pattern при этом не инвертируется.
Следовательно:
- Pattern UP остается UP;
- Pattern DN остается DN;
- Pattern NO остается NO.
Совместимость Trend и Pattern проверяется позднее в decision conjunction.
## 6. Correction для базового Pattern
В актуальных правилах открытия базовое условие Pattern сформулировано через согласованное направление компонентов.
На этой стадии нет достаточного основания вводить дополнительную блокировку только потому, что один из уровней имеет признак correction, если его направление остается согласованным.
Следовательно production-код не должен получать новое correction-правило без отдельного доказательства.
## 7. Расширенные графические паттерны
Авторские материалы отдельно используют понятия:
- паттерн разворота дневного тренда;
- паттерн разворота внутридневного тренда;
- восстановление тренда;
- другие стандартные графические паттерны SWT.
Они участвуют в более сложной логике, включая закрытие позиции, CloseByRT и SafeModeClose.
Эта логика НЕ считается автоматически эквивалентной базовому Pattern открытия.
Статус: отдельное требование AS-PATTERN-002.
## 8. Проверка текущего sig_pattern.mqh
Текущая функция:
- требует valid для Hourly, IDay, Daily;
- требует одинаковое ненулевое направление всех трех;
- возвращает UP/DN при полном согласовании;
- иначе возвращает NO;
- не зависит от ContrTrend.
Структурно это соответствует базовому Pattern актуальных правил открытия.
Production-код пока не менять.
## 9. Следующий шаг
До изменения sig_pattern.mqh:
1. создать PATTERN_BASE_MATRIX;
2. проверить UP / DN / conflict / invalid / NO;
3. отдельно проверить независимость от correction flags;
4. получить runtime-safe self-test;
5. только после PASS переводить AS-PATTERN-001 в IMPLEMENTED/PASS.
AS-PATTERN-002 остается PARTIAL/MISSING до отдельного исследования графических паттернов разворота и восстановления.
